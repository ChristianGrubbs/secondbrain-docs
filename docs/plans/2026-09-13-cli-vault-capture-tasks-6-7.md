## Invariants carried into both tasks

**Partially present derived state must never read as an empty answer.** Only a genuinely never-built collection has neither a pointer nor any generations. Absence, invalidity and corruption are distinct from that state. A damaged collection must recover from the vault or visibly fail the retrieval operation; it must not return `status: ok` with an empty result as if the query honestly missed. Apply this on both search and capture/upsert entry paths.

Capture success and retrieval readiness remain separate. Exit 0 means useful publication is complete, including its MOC link; `index: pending` may accompany it. Exit 2 means useful but incomplete publication/capture, 1 means no useful publication, and 130 means cancellation. Clients inspect the full JSON envelope and index status, preserve stderr diagnostics, and never translate an operation failure or omitted/stale result into an honest miss. Search may report omissions with exit 0; do not promise a new exit contract without an explicit tested change.

All vault access uses `obsidian-cli`. Prove `OBSIDIAN_VAULT` points at the throwaway vault before a mutating fixture, then assert the live vault is untouched. Test actual CLI processes as well as fakes: exit 1 alone cannot distinguish missing paths, unavailable backends and heading errors. Index repair deletes/rebuilds only derived generations; durable journals and ownership records survive. No original source fetch, embedding call, telemetry call or listener is permitted for retrieval/reindex.

Use Node 22 for new qualification/install work per the repository contract. Previous runs recorded Node `v26.8.2`; those results are historical evidence, not Node 22 qualification. Record actual Node/ABI, architecture, native SQLite loads and Chromium version before running the matrix. Any intended toolchain-policy change must be resolved explicitly rather than inferred from a successful native import.
